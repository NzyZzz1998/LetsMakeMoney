# v1.0.2 Bugfix Log

## V102-BUG-001 启动时短暂误报无法计算

### 根因

应用启动后立即请求权威收入快照。原生侧在配置与运行状态尚未完全就绪时可能短暂返回 `calculation_unavailable`，前端把首次瞬时结果直接转换为失败状态；稍后的同步成功，因此形成可见的假阴性。

### 修复

- 仅在尚无权威快照且错误为 `calculation_unavailable` 时进行有限重试。
- 重试期间保持加载状态，不显示失败。
- 重试次数有上限，避免真实故障无限等待。
- `invalid_work_hours` 等真实配置错误继续立即显示。
- 记录 `earnings.authoritative_sync.retry_scheduled`，便于验收区分瞬时重试和最终失败。
- 组件卸载或同步成功后清理重试计时器。

### 不改动边界

- 不修改收入、日历、日期调整、跨夜班次或金额公式。
- 不掩盖真实错误。
- 不处理多窗口重复同步候选。
- 不扩展 v1.0.2 产品范围。

- 日志：首次瞬时不可用记录 `earnings.authoritative_sync.retry_scheduled`，随后 `startup_retry` 成功，没有最终失败事件。

## V102-BUG-006 复用 Settings/Wizard 时遗留关闭确认框

### 现象

在 Settings 或 Wizard 中产生未保存更改，确认放弃并隐藏窗口后，再次显示同一个复用窗口，旧的关闭确认状态可能继续保留，导致窗口打开时立即出现上一次的确认框。

### 根因

确认回调执行 `config.cancel()` 和隐藏窗口前，没有把组件内的 `confirmClose` 状态重置为 `false`。Tauri 隐藏窗口不会销毁 React 组件，因此该状态会跨隐藏/显示继续存在。

### 修复

- Settings 的放弃确认回调先执行 `setConfirmClose(false)`，再取消草稿并隐藏窗口。
- Wizard 使用相同顺序；首次配置退出语义保持不变。
- 增加定向静态回归，要求两处确认回调都在 `config.cancel()` 前清理关闭状态。
- 不改变保存、取消、配置持久化或窗口生命周期合同。

### TDD 与验证

- 放弃后主题从深色恢复为浅色：通过。
- 再次打开 Settings：没有遗留确认框，浅色仍选中，状态显示“没有未保存的更改”。

- 日志证据：Settings 隐藏后记录 `theme.preview_applied theme=light reason=draft_discarded`，再次显示完成到 `window.shown`。

### 剩余系统边界

## V102-BUG-007 配置完成后复用 Wizard 仍使用首次配置退出语义

### 状态

已关闭，不构成发布阻塞。

### 现象

项目所有者完成首次配置后，通过 Windows 原生托盘菜单点击“重新配置”。Wizard 能从第 1 步显示，但关闭时错误弹出：

- 标题：“退出首次配置？”
- 说明：“完成配置后才能开始使用。你可以继续配置，或退出应用。”
- 危险操作：“退出应用”

已配置用户的正确语义应是放弃本次重新配置并保留现有配置，不应提示退出整个应用。

### 根因

- Wizard 的 `firstRun` 在 React 组件首次挂载时调用 `configuration_initialized` 获取。
- 首次配置保存成功后，Rust 已把 `configuration_state` 更新为 `true`。
- Tauri 隐藏 Wizard 时不会销毁 WebView；再次从托盘显示时，`lmm:window-shown` 只重置步骤、关闭确认和休息输入状态，没有刷新 `firstRun`。
- 因此同一进程内复用 Wizard 时，关闭确认仍使用首次配置分支。

该问题与 `V102-BUG-006` 不同：`V102-BUG-006` 是旧 `confirmClose` 残留，本问题是权威配置状态变化后派生的首次运行状态失效。

### 证据

- 截图：`.tmp_acceptance/v1.0.2-final-20260728-174755/evidence/manual-wizard-reopen-first-run-dialog.png`
- 截图 SHA256：`97758D9FE3BE8573C8084C67064C5D3A2456B7474BF53BA28968D61ADA84F422`
- 日志：`.tmp_acceptance/v1.0.2-final-20260728-174755/evidence/manual-tray-and-wizard-debug.log`

### 最小修复方向

1. 首次配置保存成功后立即把前端 `firstRun` 更新为 `false`。
2. 每次收到 `lmm:window-shown` 时重新读取 `configuration_initialized` 权威状态，避免复用 WebView 持有过期值。
3. 防止异步读取竞态把旧结果重新写回。

- 再次从托盘打开：从第 1 步开始，无遗留确认框。
