# LetsMakeMoney Windows v1.0 Bugfix Log

## V10-BUG-001 首次启动未进入 Wizard

- 现象：配置文件不存在时载入默认值，应用误认为已经完成配置。
- 修复：增加显式配置初始化状态；缺失或损坏配置时隐藏迷你视图并显示 Wizard。
- 结果：最终独立候选真实首次启动进入 Wizard，日志记录 `wizard.opened reason=config_missing_or_invalid`。

## V10-BUG-002 Wizard 完成后 Settings 使用旧草稿

- 现象：Settings 在应用启动时已创建配置草稿，Wizard 完成后首次打开仍显示旧值。
- 修复：配置模型在窗口重新获得焦点时刷新当前配置；存在未保存输入时不覆盖草稿。
- 结果：Wizard 保存月薪 `10000` 后，Settings 首次打开立即显示 `10000`。

## V10-BUG-003 跨窗口事件权限导致保存假失败

- 现象：尝试通过 Tauri event 广播配置变化时，ACL 拒绝事件发送，配置已写入但 UI 报告保存失败。
- 修复：移除未授权事件广播，改用窗口焦点刷新，不改变真实写入失败处理。
- 结果：最终候选不再出现 ACL 假失败；成功、无变化和真实失败语义保持独立。

## V10-BUG-004 迷你收入视图无法拖动

- 现象：迷你收入视图顶部只有极窄的不可见拖动区域，实际拖动窗口不移动，位置也不会更新。
- 根因：拖动入口缺少可发现性；Tauri v2 前端窗口拖动 API 未获得 `core:window:allow-start-dragging` 权限；配置虽已有 `mini_window_position`，运行时未形成移动、保存和恢复闭环。
- 修复：
  - 增加 `76×20` 可见顶部拖动柄，只响应鼠标左键。
  - 使用 Tauri 官方 `getCurrentWindow().startDragging()`，并仅向 `mini` 窗口授予最小拖动权限。
  - 监听 `WindowEvent::Moved`，300ms 防抖保存位置；启动时恢复位置并执行屏幕安全回落。
  - 增加拖动权限、区域、位置保存与恢复的静态门禁。
- 结果：真实 Windows 鼠标将窗口由 `(1108, 636)` 拖至 `(988, 706)`；配置和日志同步更新，重启后位置保持，主内容点击仍可打开今日工作台。
- 候选证据：`.tmp_acceptance/v1.0-drag-capability-20260724-234710/`。
