# LetsMakeMoney Windows v1.0 Bugfix Log

## V10-BUG-001 首次启动未进入 Wizard

- 现象：配置文件不存在时载入默认值，应用误认为已经完成配置。
- 修复：增加显式配置初始化状态；缺失或损坏配置时隐藏迷你视图并显示 Wizard。
- 结果：最终独立候选真实首次启动进入 Wizard，日志记录 `wizard.opened reason=config_missing_or_invalid`。

## V10-BUG-002 Wizard 完成后 Settings 使用旧草稿

- 现象：Settings 在应用启动时已创建配置草稿，Wizard 完成后首次打开仍显示旧值。
- 修复：配置模型在窗口重新获得焦点时刷新当前配置；存在未保存输入时不覆盖草稿。
- 结果：Wizard 保存月薪 `10000` 后，Settings 首次打开立即显示 `10000`。

## V10-BUG-003 跨窗口事件权限导致保存假失败

- 现象：尝试通过 Tauri event 广播配置变化时，ACL 拒绝事件发送，配置已写入但 UI 报告保存失败。
- 修复：移除未授权事件广播，改用窗口焦点刷新，不改变真实写入失败处理。
- 结果：最终候选不再出现 ACL 假失败；成功、无变化和真实失败语义保持独立。

## V10-BUG-004 迷你收入视图无法拖动

- 现象：迷你收入视图顶部只有极窄的不可见拖动区域，实际拖动窗口不移动，位置也不会更新。
- 根因：拖动入口缺少可发现性；Tauri v2 前端窗口拖动 API 未获得 `core:window:allow-start-dragging` 权限；配置虽已有 `mini_window_position`，运行时未形成移动、保存和恢复闭环。
- 修复：
  - 增加 `76×20` 可见顶部拖动柄，只响应鼠标左键。
  - 使用 Tauri 官方 `getCurrentWindow().startDragging()`，并仅向 `mini` 窗口授予最小拖动权限。
  - 监听 `WindowEvent::Moved`，300ms 防抖保存位置；启动时恢复位置并执行屏幕安全回落。
  - 增加拖动权限、区域、位置保存与恢复的静态门禁。
- 结果：真实 Windows 鼠标将窗口由 `(1108, 636)` 拖至 `(988, 706)`；配置和日志同步更新，重启后位置保持，主内容点击仍可打开今日工作台。
- 候选证据：`.tmp_acceptance/v1.0-drag-capability-20260724-234710/`。

## V10-BUG-005 Wizard 工作日预览固定为 23 天

- 现象：首次配置中切换双休、单休和大小周时，“预计本月工作日”始终显示 `23 天`。
- 根因：Wizard 使用了写死的展示文案，没有读取当前配置草稿，也没有调用正式工作日计算引擎。
- 修复：增加配置草稿驱动的月工作日预览，复用 Rust `calculate_month_salary`；大小周未明确选择本周类型时不显示推测值。
- 结果：2026 年 7 月双休为 23 天、单休为 27 天、大小周为 25 天；Rust、M4、聚合验证、打包与包体验证全部通过。

## V10-BUG-006 窗口拖拽、日历导航与设置页布局

- 现象：新窗口默认位置不稳定；今日工作台和 Settings 只能依赖标题区域拖动；Calendar 无法切换月份；Settings 存在重复分隔线和标题间距过紧；重新配置可能保留上一次 Wizard 步骤。
- 修复：

  - Calendar 增加上月、下月导航并按目标月份重新读取正式 Rust 日历结果；侧栏日历入口改为简洁文字图标。
  - Settings 的“关于”区域只保留一条分隔线，“工作与午休”标题与表单保持一致间距。
  - 每次通过“重新配置”显示 Wizard 时重置到第 1 步，不恢复上次停留步骤。
- 结果：M1 9/9、M3 17/17、M4 15/15、Rust 16/16、聚合验证、打包和包体验证通过；真实候选确认 2026 年 7 月可切换至 8 月，Settings 两处分隔线与间距已修正。

## V10-BUG-007 发布版启动时出现控制台窗口

- 现象：从便携包启动 `LetsMakeMoney.exe` 时，同时出现 PowerShell/控制台窗口。
- 根因：Rust 二进制入口缺少 Windows GUI 子系统声明，Release EXE 仍按控制台程序构建。
- 修复：
  - 在 `src-tauri/src/main.rs` 增加 Tauri 标准 `windows_subsystem = "windows"` Release 声明。
  - Debug 构建继续保留控制台，方便本地排查。
  - 增加静态门禁，防止入口声明被误删。
- 结果：定向检查确认新 Release EXE 的 PE Subsystem 为 `2 (Windows GUI)`；契约验证、打包和包体验证通过，新解压候选已重新启动。
- 边界：本次生成包记录 `source_tree_dirty=true`，属于定向候选，不替代上文已锁定的干净 Stable 候选。

## V10-BUG-008 全窗口拖动不稳定与午休单位折行

- 现象：依赖 WebView 系统拖动入口和 `220ms` 长按时，普通内容区域拖动不稳定；Wizard 的“小时”可能被压缩为上下两行。
- 根因：系统拖动调用在透明、置顶和多窗口 WebView 环境中的触发链路不稳定；单位区域允许收缩和换行。
- 修复：
  - 使用鼠标屏幕坐标和原生窗口起点计算目标位置，移动超过 `5px` 后进入拖动。
  - 仅在确认发生拖动后捕获指针，避免普通点击被吞掉。
  - 迷你收入视图允许整个非排除区域拖动；今日工作台、Settings 和 Wizard 排除按钮、输入框、选择器、链接和开关。
  - 单位区域禁止收缩和换行，保持“2 小时”横排。
- 结果：Computer Use 已确认迷你收入视图、今日工作台、Settings 和 Wizard 均可从普通文字或空白区域移动；Wizard 午休单位保持单行。M3 `20/20`、M1 `9/9`、M4 `15/15`、契约检查 `6/6`、Rust 包测试 `4/4` 和包体验证通过。
- 定向候选：Zip SHA256 `12712A9EBE0145AF3503B874CD5DC219B5C603961AB557F6404B172144A61F03`，EXE SHA256 `206D2FAE37A85C5D067600D4B75154439212790C4050ED62B92133CEEFB09EE6`。
- 边界：本次未修改收入计算、日历或配置语义；候选记录 `source_tree_dirty=true`，最终发布仍需从干净提交重新打包。

## V10-BUG-009 午休时长无法连续输入小数

- 现象：午休时长虽声明小数键盘，但输入内容每次变化都会立即转成数字；键入 `0.` 时会立刻变回 `0`，无法继续输入小数位。
- 根因：输入中的文本和参与推算的数值共用同一数字状态，丢失了小数点等尚未完成的输入状态。
- 修复：
  - 使用独立文本状态保留输入过程，允许逗号或小数点以及至多两位小数。
  - 仅在内容可解析为非负数时更新午休结束和推算下班时间。
  - 离开输入框时规范化显示，不在输入过程中提前取整。
  - 新增小数输入静态门禁。
- 结果：真实 GUI 输入 `1.5` 后显示保持为 `1.5 小时`，午休区间更新为 `12:00–13:30`，推算下班时间更新为 `17:30`，有效工时保持 8 小时。M4 `16/16`、Rust 包测试 `4/4` 和包体验证通过。
- 定向候选：Zip SHA256 `91F672A14C2432F232DBE2F90EDF9027C3FB5C02E75BBC12FF2D2325C2A80DB4`，EXE SHA256 `ECFDFAB4BE44EF24EA738CA7821BE3EC6F477CDBA5248A34D0BC5B343ED5F0E0`。
- 边界：未修改每日有效工时、工资换算或持久化字段；配置仍保存午休开始和结束时间。

## V10-BUG-010 零午休配置导致收入计算失败

- 现象：Wizard 允许将午休时长设为 `0` 并保存为相同的午休开始、结束时间，但迷你收入视图随后显示“暂时无法计算”。
- 根因：配置校验允许零午休，收入计算却将 `lunch_start_time == lunch_end_time` 判定为 `invalid_lunch_interval`，前后规则不一致。
- 修复：收入计算将相同的午休开始、结束时间解释为“当天无午休”，工作时间连续累计；结束早于开始或午休越过班次边界时仍保持失败。
- 回归：新增 `zero_lunch_duration_is_a_valid_continuous_workday`，验证 `09:30–17:30`、午休 `12:00–12:00` 在 `13:30` 处于工作中，完成 4 小时、获得半日日薪。
- 结果：Rust `17/17` 通过；新包体验证通过；真实解压包启动后迷你收入视图恢复为“上班前 / ¥0.00 / 剩余有效工时 08:00:00”。
- 定向候选：Zip SHA256 `0609FA1F8B508D5CBDFF9061D1D270AE78FB66B5666119839996346D087D1029`，EXE SHA256 `1C909C40DF6A0D10EB58D3C65A418AE618FA89C64F725547E53AA63A79509FC2`。
- 边界：该候选仍记录 `source_tree_dirty=true`，仅用于定向验收，不替代最终干净 Stable 候选。

## V10-BUG-011 收入计算失败反馈不可操作

- 现象：配置存在非法时间区间时，迷你收入视图和今日工作台只显示“暂时无法计算”，用户无法判断应检查哪类设置，也没有直接修正入口。
- 根因：前端直接展示底层错误字符串，没有稳定错误分类、面向用户的可读文案和语义日志。
- 修复：
  - 将月薪、大小周、工作时间和未知故障映射为稳定错误类别。
  - 迷你收入视图和今日工作台提供“检查设置”和“重试”两个明确出口。
  - 同一错误只记录一次 `salary.calculate.invalid`，日志仅包含错误代码，不包含配置值。
  - 零午休在今日工作台中不再生成虚假的午休时间轴；Wizard 确认页显示“无午休”。
- 结果：真实解压包在午休 `14:00–12:00` 时显示“工作时间配置有误 / 请检查上班、下班和午休时间后重试”；点击“检查设置”可直接打开“收入与作息”。日志记录 `event=salary.calculate.invalid detail=reason=invalid_lunch_interval`。
- 证据：`.tmp_acceptance/v1.0-final-20260727-094837/evidence/mini-invalid-schedule.png`、`.tmp_acceptance/v1.0-final-20260727-094837/evidence/invalid-schedule-settings-action.png`、`.tmp_acceptance/v1.0-final-20260727-094837/evidence/today-no-lunch-verified.png`。
- 边界：没有放宽非法午休区间校验；只有开始与结束相同被解释为“无午休”。
