## V106-BUG-001 主题首帧与跨窗口漂移

### 现象

v1.0.5 正式包的 `config.json` 已保存浅色主题时，Mini 与首次打开的 Workbench 仍可能采用旧深色。Settings 执行一次无变化保存后才恢复浅色。

### 根因

1. `index.html` 在 React 之前读取每个 WebView 的 `localStorage["lmm.theme"]`。
2. `theme.ts` 把预览与应用结果继续写回该缓存，形成第二持久事实源。
3. 主题监听器延迟注册且不补读快照，懒创建窗口可能错过广播。
4. Mini/Workbench 不读取配置草稿，无法自行纠正首帧。
5. Settings/Wizard 在 Rust 配置 hydration 前先持有默认草稿，缺少写入门禁。

### 修复

- Rust 新增进程内 ThemeSession，区分 persisted 与带事务 ID 的 preview，并用 revision 拒绝过期事件。
- WebView 在 React 挂载前读取 ThemeSession；失败时安全回退浅色并记录原因。
- 旧 `lmm.theme` 仅清理，不再读取或写入；浏览器开发回退只读取现有 `lmm.config`。
- 监听器注册完成后立即补读权威快照；窗口 shown 时再次收敛。
- preview、commit、revert 使用稳定事务 ID，过期事务不能清理较新的预览。
- Settings/Wizard 在 hydration 完成前只显示加载/错误状态，事务层拒绝未 hydration 的保存。
- 增加 `theme.loaded`、`theme.window_applied`、`theme.preview_applied`、`theme.saved`、`theme.preview_reverted` 和 bootstrap 失败日志。

## V106-BUG-002 原生关闭绕过主题事务

### 现象

Settings 或 Wizard 已产生未保存主题预览时，点击窗口内关闭按钮会显示确认；但原生 Alt+F4 曾直接隐藏窗口。Settings 隐藏后 Mini 与 Workbench 仍停留在 preview 主题，未恢复 persisted 配置。

### 根因

Tauri 的 `CloseRequested` 处理器对所有辅助窗口统一执行原生隐藏，没有把 Settings/Wizard 的关闭意图交给 React。窗口内按钮和原生关闭因此走了两套不同事务路径。

### 修复

- Rust 对 `settings`、`wizard` 的原生关闭请求发送 `lmm:window-close-requested`，记录 `window.close_requested route=react`。
- React 新增原生关闭请求监听，复用既有 `requestClose()`、确认、放弃和回滚逻辑。
- Workbench 等不持有配置草稿的窗口继续使用既有原生隐藏策略。
- 增加窗口表面行为门禁，证明 Settings/Wizard 路由到 React，其他窗口不被错误改写。

### 验证

- 窗口表面行为：18/18 通过。
- Settings：深色草稿上 Alt+F4 显示“放弃未保存的更改?”；放弃后三窗口恢复浅色，配置 SHA256 不变。
- Settings：persisted dark 上预览浅色，Alt+F4 放弃后三窗口恢复深色。
- Wizard：dark 首帧正确；Alt+F4 显示“放弃本次配置?”，放弃后恢复 persisted dark。
- 日志形成 `window.close_requested -> theme.preview_reverted -> window.hidden -> theme.window_applied` 闭环。
