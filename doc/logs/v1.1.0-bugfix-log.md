# LetsMakeMoney Windows v1.1.0 缺陷记录

## V110-BUG-001 拖拽期间窗口失焦后输入状态卡死

| 字段 | 内容 |
| --- | --- |
| 状态 | 已修复；定向复验通过，最终干净候选已重建 |
| 严重度 | Blocker |
| 影响范围 | Classic 桌宠输入仲裁、拖拽收势、窗口生命周期 |
| 首次发现 | 125% DPI 发布前验收，拖拽期间调用 Windows 截图 |

### 复现与影响

1. 长按 Classic 约 500ms 并开始拖动。
2. 鼠标仍按下时触发 Windows 截图，桌宠 WebView 失去焦点。
3. 截图流程截断正常的 `pointerup` / `pointercancel`，运行时保持 `dragging`。
4. 鼠标再次靠近会继续移动桌宠，只能通过隐藏并恢复窗口解除状态。

旧候选日志证据为：`pet_input_press_pending`（序号 2089）→ `pet_input_drag_started`（2090）→ `browser_lifecycle_observed: blur`（2096）；直到 15 秒后窗口隐藏才出现 `pet_input_drag_released(cancelled:true, reason:window_hidden)`（2128）。因此旧候选 `V110-20260812T163314Z-d9d51cfe-clean` 已被淘汰，不得发布。

### 根因

输入仲裁只依赖 `pointerup` / `pointercancel` 结束活跃指针；浏览器 `blur` 没有取消输入，Canvas 也没有处理 `lostpointercapture`。截图、系统切换或其他导致指针捕获丢失的操作可以留下永久 `dragging` 状态。

### 最小修复

- 统一使用 `resetActiveInput(reason, pointerId)` 清理仲裁状态、活跃指针、移动基线和指针捕获。
- `window.blur` 使用 `window_blur` 原因取消活跃输入。
- Canvas `lostpointercapture` 使用 `lost_pointer_capture` 原因取消活跃输入。
- 中断拖拽仍播放 `run_stop`，随后收敛到最新权威基础状态。
- 新增 `pet_input_interruption_recovered` 语义日志。

### 验证

- TDD 红灯：新增静态门禁后，旧实现按预期失败 `pet drag capture-loss recovery missing`。
- 自动验证：`pet-runtime.behavior.ts` 由 3/3 增至 4/4，覆盖拖拽后 `window_blur` 取消及后续点击恢复；v1.1.0 验证和架构门禁通过。
- 真实 Windows 125% DPI：保持鼠标按下并进入跑动后触发 `Win+Shift+S`，日志序号 1685/1686/1699/1700/1701/1702/1703-1704 依次证明按下、拖拽、截图失焦、取消、收势、恢复和真实动画完成；取消原因为 `window_blur`。
- 中断恢复后再次单击可正常触发 `working_ack`，未重新进入拖拽。
- 中断恢复后再次执行普通长按拖拽，500.7ms 进入拖拽，正常释放并完整结束 `run_stop`。
- 修复提交 `7eb9f88d13b8f59e1560bfd8b58cccc8e9501d1f` 已生成最终候选 `V110-20260813T042624Z-7eb9f88d-clean`；宠物运行时行为测试 4/4 与候选包验证通过。最终 Zip 的截图中断拖拽完整人工重复仍作为发布前补证保留，不改变缺陷代码层已关闭的事实。

- 远程桌面证据未用于最终结论；2026-08-17 本机直接输入验收确认快速反向无明显积压追赶或方向延迟。

## V110-BUG-002 宠物包 manifest 哈希受工作区换行影响

| 字段 | 内容 |
| --- | --- |
| 状态 | 已修复；完整门禁、候选重建、包体审计与启动冒烟通过 |
| 严重度 | Blocker |
| 影响范围 | Classic 净化运行时包、干净复现构建、包身份门禁 |
| 首次发现 | 从最终验收文档提交执行 `package_v110.ps1` |

### 根因与影响

`0.4.1-rc.1` 的索引曾按生成时 CRLF 字节计算 manifest SHA256；仓库通过 `.gitattributes` 将文本规范化为 LF。旧工作区候选可以自洽运行，但从规范化 LF 的干净工作区重建时，`verify_pet_return_runtime.py` 会以 `pet manifest SHA256 drift` 拒绝继续，证明包身份不可复现。

### 最小修复

- 使用仓库规范化 LF 字节重新计算 manifest SHA256 与 package tree SHA256。
- 同步 `package-index.json`、Rust 锁定测试和事实文档。
- 在 Python 包合同中显式拒绝 CRLF manifest，防止生成管线再次把工作区换行状态写入包身份。
- 最终候选 `V110-20260817T031659Z-71616e2e-clean` 已从干净提交生成；完整 current gate、91/91 Rust tests、Clippy、Python/Rust 包合同、候选包审计和启动冒烟通过。

## V110-BUG-004 Mini 贴边完成时被指针进入事件取消收起

| 字段 | 内容 |
| --- | --- |
| 状态 | 已修复；行为测试与 dirty 候选真实窗口证据通过，等待干净候选重建 |
| 严重度 | Blocker |
| 影响范围 | Mini 隐私自动隐藏、拖拽完成状态机 |
| 首次发现 | 项目所有者将 Mini 贴到屏幕右边缘后仍完整显示 |

### 根因与修复

- `dragCompleted()` 等待原生窗口移动完成时，窗口位置变化会先触发 `pointerenter`。
- 旧 `pointerEntered()` 会增加 generation，导致仍在途的贴边完成结果失效，因此必须再次交互后才可能收起。
- 拖拽锁持有期间现在忽略 `pointerenter`，由拖拽完成事务唯一决定 dock 与 retract。
- 新增 deferred `completeDrag` 行为测试，稳定复现并保护该竞态。

### 定向证据

- dirty 候选日志完整记录 `mini.edge_dock.detected side=right` → `mini.edge.retract.scheduled source=drag_complete` → `mini.edge_dock.retracted` → `mini.edge.retract.completed phase=retracted`。
- 恢复项目所有者原配置并重启后，真实窗口为右侧 `40×108` 隐私竖条，不再保持完整 Mini。

## V110-BUG-007 原生吸附期间的指针/焦点抖动丢弃自动收起

| 字段 | 内容 |
| --- | --- |
| 状态 | 已修复；自动回归通过，等待新 clean 候选重复贴边复验 |
| 严重度 | Blocker |
| 影响范围 | Mini 隐私自动隐藏、原生吸附、指针与焦点仲裁 |
| 首次发现 | Mini 能吸附到屏幕边缘，但并非每次都会自动收起 |

### 根因与修复

- 旧控制器用同一个 generation 同时管理收起计时器和拖拽完成事务。
- `completeDrag()` 等待原生窗口吸附时，`pointerleave`、焦点变化或锁释放会使 generation 变化；已成功的吸附结果随后被误判为过期，无法启动首次收起计时。
- 现在为拖拽事务使用独立版本号。指针和焦点事件仍可取消陈旧计时器，但不能丢弃本次原生吸附结果。
- 原生确认贴边后主动启动唯一的 600ms 收起计时；首次收起不再要求额外点击或 `pointerleave`。

### 验证

- 新行为测试在 `completeDrag()` 在途期间注入 `pointerleave` 和焦点锁开关，旧实现稳定失败，修复后能提交 dock 并仅保留一个收起计时器。
- Mini 自动隐藏行为、架构门禁、TypeScript strict 与 Vite 生产构建通过。
- 仍需在新 clean Zip 中对左右边缘各重复至少 10 次，确认每次释放后均自动收起，移入展开、移出再收起正常。
