# LetsMakeMoney Windows v1.1.0 缺陷记录

## V110-BUG-001 拖拽期间窗口失焦后输入状态卡死

| 字段 | 内容 |
| --- | --- |
| 状态 | 已修复；定向复验通过，最终干净候选已重建 |
| 严重度 | Blocker |
| 影响范围 | Classic 桌宠输入仲裁、拖拽收势、窗口生命周期 |
| 首次发现 | 125% DPI 发布前验收，拖拽期间调用 Windows 截图 |

### 复现与影响

1. 长按 Classic 约 500ms 并开始拖动。
2. 鼠标仍按下时触发 Windows 截图，桌宠 WebView 失去焦点。
3. 截图流程截断正常的 `pointerup` / `pointercancel`，运行时保持 `dragging`。
4. 鼠标再次靠近会继续移动桌宠，只能通过隐藏并恢复窗口解除状态。

旧候选日志证据为：`pet_input_press_pending`（序号 2089）→ `pet_input_drag_started`（2090）→ `browser_lifecycle_observed: blur`（2096）；直到 15 秒后窗口隐藏才出现 `pet_input_drag_released(cancelled:true, reason:window_hidden)`（2128）。因此旧候选 `V110-20260812T163314Z-d9d51cfe-clean` 已被淘汰，不得发布。

### 根因

输入仲裁只依赖 `pointerup` / `pointercancel` 结束活跃指针；浏览器 `blur` 没有取消输入，Canvas 也没有处理 `lostpointercapture`。截图、系统切换或其他导致指针捕获丢失的操作可以留下永久 `dragging` 状态。

### 最小修复

- 统一使用 `resetActiveInput(reason, pointerId)` 清理仲裁状态、活跃指针、移动基线和指针捕获。
- `window.blur` 使用 `window_blur` 原因取消活跃输入。
- Canvas `lostpointercapture` 使用 `lost_pointer_capture` 原因取消活跃输入。
- 中断拖拽仍播放 `run_stop`，随后收敛到最新权威基础状态。
- 新增 `pet_input_interruption_recovered` 语义日志。

### 验证

- TDD 红灯：新增静态门禁后，旧实现按预期失败 `pet drag capture-loss recovery missing`。
- 自动验证：`pet-runtime.behavior.ts` 由 3/3 增至 4/4，覆盖拖拽后 `window_blur` 取消及后续点击恢复；v1.1.0 验证和架构门禁通过。
- 真实 Windows 125% DPI：保持鼠标按下并进入跑动后触发 `Win+Shift+S`，日志序号 1685/1686/1699/1700/1701/1702/1703-1704 依次证明按下、拖拽、截图失焦、取消、收势、恢复和真实动画完成；取消原因为 `window_blur`。
- 中断恢复后再次单击可正常触发 `working_ack`，未重新进入拖拽。
- 中断恢复后再次执行普通长按拖拽，500.7ms 进入拖拽，正常释放并完整结束 `run_stop`。
- 修复提交 `7eb9f88d13b8f59e1560bfd8b58cccc8e9501d1f` 已生成最终候选 `V110-20260813T042624Z-7eb9f88d-clean`；宠物运行时行为测试 4/4 与候选包验证通过。最终 Zip 的截图中断拖拽完整人工重复仍作为发布前补证保留，不改变缺陷代码层已关闭的事实。

- 同时验证左右镜像、100%/125%/150% DPI、动态命中区与窗口边缘。
- 不通过简单放大整张图解决，避免脚底线、命中区、窗口裁切和比例再次回归。

### 定向修正与当前证据

- 将桌宠逻辑画布由 `192×208` 扩展为 `256×208`，基础状态保持原始角色尺度并居中；拖拽动作使用透明边界裁切、预乘 Alpha 重采样、脚底线锁定和水平居中重新合成。

- `V110-20260813T055122Z-7eb9f88d-dirty` 已通过 current gate、91/91 Rust tests、Clippy、release 构建和包体审计。项目所有者通过远程环境确认体量较此前改善，但远程拖拽不能证明真实本机手感，因此不得写成拖拽通过。

## V110-UX-002 拖拽移动积压导致跟手性下降

| 字段 | 内容 |
| --- | --- |
| 状态 | 已实现合并位移调度；自动门禁通过，待本机手感补证 |
| 类型 | Tauri IPC 调度与拖拽交互 |
| 根因 | 每个 `pointermove` 都串行排入原生 IPC Promise 队列，鼠标移动速度高于窗口移动完成速度时产生积压追赶 |

### 修正与门禁

- 任一时刻最多保留一个原生窗口移动请求；请求执行期间的新位移累计为一个待处理增量，完成后一次性排出。
- 截图、失焦、隐藏和输入取消时丢弃尚未发送的陈旧位移，避免恢复后继续追赶旧轨迹。
- 新增行为测试覆盖单请求在途、位移合并和中断清空；宠物运行时行为测试为 6/6。
- 远程桌面会改变指针采样、合成和窗口传输延迟，当前仅记录自动证据，不以远程手感替代本机通过结论。
