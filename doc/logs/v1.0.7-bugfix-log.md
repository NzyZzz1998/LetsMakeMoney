## V107-BUG-001 打包应用无法读取版本

| 字段 | 内容 |
| --- | --- |
| 状态 | 已修复，自动测试与真实 GUI 定向复验通过 |
| 严重度 | Blocker |
| 发现阶段 | `V107-ACC-012` 核心回归 |
| 用户影响 | 关于页显示“读取失败”，更新检查入口不可用，用户无法确认版本或检查更新 |
| 复现 | 启动独立解压候选，打开 Settings 的“数据与支持”，观察版本与更新检查状态 |

| 根因判断 | 已确认：前端版本读取需要的 Tauri capability 缺失，异常被 UI 降级为“读取失败” |
| 最小修复 | 只增加读取应用版本所需的最小 capability；保留版本格式校验和失败降级，不扩大其他 app 权限 |
| 自动测试 | capability 合同检查；桌面 reader 成功、权限失败、非法版本和浏览器预览测试 |

| 回退 | 撤销 capability 变更并恢复当前配置；不得通过硬编码版本绕过权限链 |
| 实际修复 | `src-tauri/capabilities/mini-window.json` 增加最小权限 `core:app:allow-version`，未授予 broad app capability |
| 修复测试 | `verify_v107_m1.py` 增加权限存在与 broad 权限缺失的合同检查；current 聚合门禁通过 |
| 修复候选 | `V107-M7-DIRTY-20260804-02`；EXE SHA256 `37DE58BCD9FE1F0FE41C0F31AA640E68C4A07004A9E9BC6E4C26B0FB6236FB98` |
| GUI 复验 | Settings“数据与支持”显示版本 `1.0.7`；点击检查更新返回“当前已是最新版本”，见 `ACC-FIX-006`、`ACC-FIX-007` |

## V107-BUG-002 Workbench 第二次打开超时

| 字段 | 内容 |
| --- | --- |
| 状态 | 已修复，自动测试与真实 GUI 定向复验通过 |
| 严重度 | Blocker |
| 发现阶段 | `V107-ACC-004` Mini/Workbench 显示事务 |
| 用户影响 | 首次关闭今日详情后，再次打开会在约 8 秒后自动消失，Mini/Workbench 事务无法稳定复用 |
| 复现 | 打开 Workbench，关闭后恢复 Mini，再次打开 Workbench并等待 8 秒；第二次和后续打开均会被隐藏 |
| 日志证据 | `window.visibility_lease.requested` 后出现 `window.visibility_lease.timeout`，随后 `window.hidden source=workbench_initialization_timeout` |
| 代码证据 | `App.tsx` 的 `WorkbenchWindow` 仅在挂载时调用一次 `workbenchReady()`；Tauri 隐藏窗口时复用既有 WebView，不会重新挂载 |
| 根因判断 | 已确认：每次 visibility transaction 都要求 ready，但前端只在首个 WebView mount 发出确认 |
| 最小修复 | 为每次 Workbench 显示事务建立幂等、带 transaction 语义的 ready 确认；不得移除 watchdog 或简单延长超时 |
| 自动测试 | 连续打开/关闭至少三次；晚到 ready、重复 ready、失败补偿和 Mini 前态恢复 |
| 定向复验 | 连续打开/关闭三次均稳定；每次 requested/ready/open/closed 日志按事务成对；无 timeout |
| 回退 | 回退逐次 ready 机制并保留现有 visibility lease；不得退回无补偿的直接 show/hide |
| 实际修复 | 复用既有 Workbench WebView 时，由原生窗口策略确认当前精确 transaction；拒绝 stale transaction，保留 8 秒 watchdog 与失败补偿 |
| 修复测试 | Rust 新增 `reused_workbench_is_confirmed_without_waiting_for_a_remount`；Rust 67/67 与 current 聚合门禁通过 |
| 修复候选 | `V107-M7-DIRTY-20260804-02`；Zip SHA256 `EF57B0361B379B0D009EBD014B8717B4D7FA50C08330B297C3071A8171E56D47` |
| GUI 与日志复验 | 连续打开/关闭三次；第 2、3 次各等待 9.5 秒仍保持可见。三个事务均有 requested/open/closed，timeout 与 initialization timeout 均为 0 |

## V107-BUG-003 六周日历在高 DPI 下摘要重叠

| 字段 | 内容 |
| --- | --- |
| 状态 | 已修复，自动测试与真实 125%/150% DPI 定向复验通过 |
| 严重度 | Major，发布 DPI 门禁 |
| 发现阶段 | `V107-M4-009`、`V107-M5-009` 与 `V107-ACC-011` |
| 用户影响 | 在 125%/150% 缩放下查看六周月份时，月度总结被纵向压缩，说明、指标标签和值发生重叠，影响读取与视觉可信度 |
| 复现 | 将 Windows 显示缩放设为 125% 或 150%，打开 2026 年 8 月六周日历，观察底部月度总结 |
| 首次失败证据 | `DPI-125-003-calendar-six-week-overlap.jpg`、`DPI-150-007-calendar-six-week-overlap`；失败证据继续保留 |
| 根因判断 | 已确认：真实实现使用纵向摘要结构，在固定 Workbench 高度和高 DPI 可用空间缩小时被压缩；原型的双列结构没有落实到生产 CSS |
| 最小修复 | 月度总结改为稳定双列结构，冻结最小高度与行高，并为长标签和值增加不换行和溢出收敛规则；不扩大 Workbench 或重写日历 |
| 自动测试 | `verify_v107_m4.py` 冻结双列、最小高度、行高和长文本规则；v1.0.7 full current gate 通过 |
| 修复候选 | `V107-M7-DIRTY-20260804-03`；Zip SHA256 `322EB52DD01AE3B9BEE50EC3346B027C2AEA6E4669505735D01A493A3028A6E5`；EXE SHA256 `91F9EB87FBA35F7A6B3165A4E25CF05E544CDC598CB329FFC150ED416072BA46` |
| GUI 复验 | 真实 Windows 125% 与 150% DPI 下，2026 年 8 月六周日期、月度总结四项内容和图例均一屏可见，无裁切、重叠或文本溢出 |
| 修复后证据 | `DPI-125-calendar-six-week-summary-fixed.png`、`DPI-150-calendar-six-week-summary-fixed.png`；脱敏摘要为 `evidence/acceptance-dpi-summary.json` |
| 回退 | 回退本次摘要布局并恢复发布阻塞；不得通过缩小系统字体或扩大整个窗口掩盖问题 |
