## V105-BUG-001 Mini 首次贴边不及时收起

- 状态：已修复并定向验证；FR-003 关闭。
- 严重度：Major / P0 隐私。
- 复现：指针位于 Mini 内时开始拖动并释放到左侧或右侧屏幕边缘，不额外触发 `pointerleave`；当前控制器不会启动 600ms 收起 timer。
- 根因：`dragCompleted()` 应用原生 dock 结果后仍保留 `pointerInside=true`，而 `eligible()` 要求指针不在窗口内。
- 自动证据：当前行为 characterization 在左右两侧均通过；M3 目标测试以 `M2_RED_NO_POINTERLEAVE_RETRACT` 按预期失败。
- 最小修复边界：仅在拖动释放时校准指针意图并重新评估收起资格；保留单 timer generation、menu/modal/focus 锁、拖回浮动取消和晚到 timer 防护。
- 回归要求：左右边缘首次收起、拖回、托盘显式找回、位置持久化和配置事务。
- 修复：拖动完成后重置过期 pointer intent，立即以释放后的 dock 状态重新评估资格；generation/token 防止晚到 timer 与原生结果覆盖新状态。
- 复验：左右边缘真实 Windows 首次释放均无需额外交互即可收起；状态机 `37/37`、Rust 几何与故障回退测试通过。

## V105-BUG-002 关闭 Workbench 后 Mini 非预期展开

- 状态：已修复并定向验证；FR-004 关闭。
- 严重度：Major / P1 隐私与窗口生命周期。
- 对象：GitHub 发布的 v1.0.4 Stable 便携包，Zip SHA256 为 `C4F28892831891A4266C4D9B12D432CD5C970BB3C9B36A6B8DB21FA2566DE50E`。
- 复现：20/20。每轮关闭 Workbench 前 Mini 均为收起态，关闭后均展开；校准轮不计入 20 轮。
- 界面身份：实际出现的是 `mini` 展开态，不是托盘菜单、Settings 或 Wizard。
- 事件证据：20 轮均有关联的普通窗口 focus；日志出现 20 条 `mini.edge_dock.revealed ... source=window_shown`，但原生 Mini `window.shown` 为 0。
- 根因：`useMiniEdgeAutoHide` 将浏览器 `focus` 与原生 `lmm:window-shown` 注册到同一个 reveal handler，普通焦点回归被错误当成显式找回。
- 最小修复边界：分离普通 focus 与 explicit shown；不得破坏托盘找回、启动恢复和用户主动恢复。
- 脱敏摘要：`doc/releases/v1.0.5/evidence/m2-characterization-summary.json`。
- 原始证据：只保存在被 Git 忽略的本地验收目录；仓库不保存完整日志、截图、金额、坐标或用户路径。
- 修复：浏览器 focus 仅建立 `focus_inside` 交互锁；只有显式 `lmm:window-shown` 才执行 `reveal("window_shown")`。托盘恢复继续发送显式 shown 事件。
- 复验：收起态 Mini 获得普通 focus 不展开；真实关闭 Workbench 后 Mini 保持收起。通知区真实鼠标找回仍留给独立 ACC，当前由原生接线和自动合同保护。
