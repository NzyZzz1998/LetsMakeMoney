> 结论状态：项目所有者已确认推荐路线，WinUI 3 已淘汰
> 推荐路线：Rust + Tauri + TypeScript/React
> 分支：`agent/v1.0-review`
> 基线 HEAD：`aa7c0b93780d7511a6551624f2eea88595cee51f`
> 验证日期：2026-07-23

## 1. 结论

三条路线使用同一套 fixture、设计 token、窗口尺寸和黄金路径实现后，当前结论是：

1. **Rust + Tauri + React 是 v1.0 推荐技术路线。** 它是唯一完成真实 GUI、高保真还原、配置事务保存、保存失败输入保留、关闭隐藏和便携 EXE 构建的路线。
2. **Godot 4.7 只保留为回退基线。** 它能稳定导出并实现托盘代码路径，但同一视觉合同下仍出现控件质感、字体、图标、密度和无障碍差距；当前保存样板也只更新内存值。
3. **WinUI 3 不进入 v1.0 主线或备选路线。** 修复 XAML 资源、主题和窗口初始化问题后，自包含样板已能真实启动并展示迷你收入视图与工作台。实机对照确认其原生 Windows 特征明显，但默认组件与窗口语言偏传统，自定义到目标质感所需成本、开发摩擦和产物规模均不符合“视觉表现最高优先级”的目标。项目所有者已明确停止该路线。
4. Tauri 仍有两个真实 Windows 硬门禁未关闭：**125%/150% 系统 DPI** 和 **通知区真实鼠标左键隐藏/找回**。因此本文件给出的是“推荐路线”，不是发布验收结论。

## 5. 保存事务证据

Tauri 真实 GUI 已验证：

1. 将月薪从 `10,000` 修改为 `12,000`，显示保存成功。
2. 不修改再次保存，显示“没有需要保存的更改”。
3. 开启受控失败后输入 `13,000`，显示可读失败原因且输入保留。
4. 失败后读取隔离配置文件，持久化值仍为 `12,000`，未被失败输入污染。

证据：

- [保存失败截图](evidence/technical-spike/tauri/save-failure.png)
- Rust 使用临时文件写入后替换目标文件。
- Rust 单元测试 2/2 通过；前端合同验证通过。

Godot 样板包含成功、无变化和失败文案，但只更新 `saved_salary` 内存变量，不能作为配置事务通过证据。

## 9. 技术决策

建议 v1.0 PRD 以以下边界展开：

- React/TypeScript：窗口界面、组件状态、视图导航和视觉回归。
- Rust/Tauri：窗口、托盘、关闭隐藏、文件事务、日志和 Windows 原生边界。
- 工资、作息、节假日与配置兼容：先形成框架无关合同，再决定落在 Rust 还是 TypeScript，不能从 Godot 直接复制两套实现。
- v0.9 Godot 版本：保留 tag、Release 与历史作为回滚基线，不作为 v1.0 新界面的并行实现。
- WinUI 3：不进入 v1.0 主线或备选；即使 Tauri 条件门禁失败，也应先回到产品与技术决策层重新评估，不自动重启 WinUI 专项。

## 10. 进入 PRD 前的最小门禁

以下项目不要求在本 Spike 中扩大实现，但必须写入 PRD 的 M0：

1. 在真实 Windows 125% 和 150% 显示缩放下检查三个窗口。
2. 用真实通知区鼠标左键完成隐藏与找回，关闭按钮仍只隐藏不退出。
3. 将构建脚本中的本机工具路径参数化，并形成新环境说明。
4. 重新设计无宠物应用图标；当前 Tauri `icon.ico` 只用于构建验证。
5. 明确 WebView2 缺失、损坏或版本异常时的提示与降级。
6. 测量包含 WebView2 子进程在内的总内存与两小时稳定性。
7. 为工资和配置兼容建立框架无关行为测试，之后才迁移完整业务。
