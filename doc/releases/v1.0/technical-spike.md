## 1. 目的

本 Spike 只回答一个问题：

> Rust + Tauri + React、C# + WinUI 3、Godot 4.7 中，哪条路线最适合稳定实现 v1.0 已确认的视觉、交互与 Windows 生命周期要求？

本阶段不迁移完整业务、不删除 v0.9 宠物代码、不生成正式发布包，也不代替 PRD 或 Acceptance。

## 2. 已确认决策

- 产品结构采用“迷你收入视图 + 今日/日历工作台”。
- 迷你收入视图默认随应用启动并常驻，可从托盘单独隐藏或找回。
- v1.0 用户可见产品不包含宠物。
- 后续正式迁移时，从活跃源码与发布包移除宠物代码和素材；v0.9 tag、Release 与历史作为恢复基线。
- 首次升级生成一次 v0.9 配置兼容备份，v1.0 活跃配置不再写入宠物字段。
- 日历只服务工作日、调休、节假日、手动调整与收入查看。
- 三条路线必须先通过硬门禁，再按 100 分评分卡比较。

## 4. 固定黄金路径

```text
启动
  → 迷你收入视图
  → 今日工作台
  → Settings 代表页
  → 保存成功 / 无变化 / 保存失败
  → 托盘隐藏 / 找回
```

三条路线必须覆盖：

- 工作中、午休、非工作日；
- normal、hover、focus、pressed、disabled、loading、success、error；
- 长金额、长中文、英文和可读错误；
- 100%、125%、150% DPI；
- 保存失败时保留输入、不污染已保存值；
- 托盘隐藏后可可靠找回。

|---|---:|---:|---|

## 6. 视觉方向

物理场景：用户在 Windows 办公桌上长时间运行一个安静的小工具，需要一眼确认收入进度，同时不被大面积装饰、过度暖色或厚重窗口打断。

- 注册：产品型、克制、清晰、可信。
- 字体：`Segoe UI Variable` 优先，数字使用 tabular figures。
- 背景：接近无色的浅灰，不使用大面积奶油/砂纸色。
- 品牌色：金币黄只用于主要操作与收入进度；绿色只用于正常/成功状态。
- 圆角：窗口 12px，普通控件 8px，标签可用 pill；不使用 24px 以上卡片圆角。
- 阴影：窗口使用单层短阴影；组件优先边界或层次色，不同时叠加宽阴影。
- 动效：按钮 120ms、popover 160ms、窗口状态 200ms；只表达反馈或空间关系，支持减少动态效果。

## 7. 硬门禁

任一路线出现下列情况即淘汰：

1. 无法生成可独立运行的 Windows 便携构建。
2. 125%/150% DPI 出现明显模糊、裁切或错位。
3. 托盘隐藏后无法可靠找回。
4. 保存失败不能保留输入并显示可读原因。
5. 依赖截图、Canvas 位图或一次性布局 hack 才能还原视觉。
6. 无法自动验证核心组件状态。
7. 依赖未声明的本机绝对路径或私有缓存。

## 8. 评分卡

| 指标 | 权重 |
|---|---:|
| 高保真还原与组件一致性 | 30 |
| 字体、图标、间距、边界和窗口质感 | 20 |
| 动效、反馈和可中断性 | 10 |
| DPI、可访问性和长内容稳定性 | 10 |
| Windows 窗口、托盘和生命周期 | 10 |
| 冷启动、内存、包体和流畅度 | 10 |
| 构建、测试和发布可维护性 | 10 |

只有通过全部硬门禁的路线才进入评分。总分差距小于 5 分时，优先比较 Windows 行为、维护复杂度和迁移风险。

## 9. 环境与执行结果

| 路线 | 实际环境 | 结果 |
|---|---|---|
| Tauri + React | Node.js 22.14.0；隔离 Rust MSVC 1.97.1；Tauri 2.11.5 | 构建、真实 GUI、保存事务通过；真系统 DPI 与真实通知区左键待补证 |
| WinUI 3 | 隔离 .NET 8 SDK；Windows App SDK 1.8 | 自包含构建与真实启动通过；实机对照后因视觉方向、开发摩擦和产物规模被项目所有者淘汰 |
| Godot 4.7 | `4.7.stable.official.5b4e0cb0f` | 导出与真实 GUI 通过；视觉、可访问性、自动状态验证和配置事务不足 |

工具链问题属于 Spike 证据：三条路线均使用隔离工具链或明确版本完成验证。当前脚本仍包含本机工具位置，正式工程必须参数化，不能将该路径合同带入 v1.0。

完整结果见：`doc/releases/v1.0/technical-spike-results.md`。
