## 需补测试后治理

### V107-SLIM-004 前端页面编排

- 对象：`apps/windows-v1/src/App.tsx`
- 证据状态：已确认
- 调用与所有权：应用路由、Workbench、Today、Calendar、Settings、Wizard、弹窗和窗口入口仍集中于该文件；属于活跃入口，不是死代码。
- 候选动作：先选一个稳定边界，例如 Settings 或 Wizard，提取页面组件和页面专属状态；保留现有 service、hook 和事件接口。
- 补测要求：路由入口、保存成功/无变化/失败、关闭语义、主题和窗口生命周期组合测试。
- 删除验证：原代码只有在新组件被真实路由调用、行为测试和 GUI 定向回归通过后才能移除。
- 预计收益：中；降低单文件阅读和冲突成本。
- 风险：中；一次提取多个窗口会放大回归面。

### V107-SLIM-005 Dashboard 与日历模型

- 对象：`apps/windows-v1/src/model.ts`
- 证据状态：已确认
- 调用与所有权：Mini 与 Workbench 都依赖 Dashboard、日历 cache、日期调整和 timer 生命周期逻辑。
- 候选动作：优先提取 calendar repository/hook，保持既有导出 API；本版不引入新的全局状态框架。
- 补测要求：30 秒权威同步、1 秒本地呈现、失败保留有效快照、隐藏/恢复、跨夜 owner date、日期调整事务。
- 删除验证：调用方切换后执行静态导入扫描、前端全套行为测试和真实双窗口回归。
- 预计收益：中到高；减少日历变更影响 Dashboard 的概率。
- 风险：高；计时与 cache 的细微变化会影响收入可信度。

### V107-SLIM-006 Rust 应用编排

- 对象：`apps/windows-v1/src-tauri/src/lib.rs`
- 证据状态：已确认
- 调用与所有权：Tauri command 注册、窗口规格、托盘、Mini edge、WebView 生命周期和 `run()` 均为活跃路径。
- 候选动作：先提取纯 `WindowSpec` 与错误映射；之后最多再选择 tray 或 mini-edge 中一个边界。
- 补测要求：`cargo test`、`clippy`、命令名与注册不变、窗口找回、托盘、贴边隐藏、DPI 和 GUI 回归。
- 删除验证：新模块接管所有调用后才删除原实现；每个边界独立提交并可回退。
- 预计收益：高；缩小 Windows 行为修改的认知范围。
- 风险：高；平台生命周期问题通常只在真实桌面暴露。

### V107-SLIM-007 窗口失败 fallback

- 对象：`App.tsx`、`WindowFrame.tsx`、`services/windowService.ts`
- 证据状态：高度可能
- 当前问题：桌面 `show` 失败会退化为 query 导航，`hide` 失败被静默吞掉；这可能掩盖 native 故障。
- 候选动作：先区分 browser preview 与 desktop runtime，再统一可诊断失败语义。
- 补测要求：浏览器预览、Tauri 成功、invoke 失败、窗口不存在、hide 失败、日志与用户反馈。
- 删除验证：旧 fallback 只能在 browser preview 兼容测试和真实桌面失败注入通过后移除。
- 预计收益：中；减少隐式分支和不可诊断状态。
- 风险：中；错误移除会破坏 HTML 原型/浏览器预览。

## 删除验证方案

任何候选真正删除前，按以下顺序执行：

1. **身份冻结**：记录分支、HEAD、工作区、候选文件哈希和正式发布基线。
2. **调用扫描**：检查 TypeScript/Rust import、PowerShell/Python 调用、Tauri command/event 字符串、配置字段、文档链接和 GitHub workflow。
3. **动态入口**：检查窗口 label、托盘菜单、query 路由、资源路径、运行时 `include_*`、配置迁移和反射式字符串。
4. **历史作用**：核对 release 文档、tag、回归脚本和旧配置升级路径。
5. **受控删除**：一次只处理一个所有权边界，不混入功能改动。
6. **自动验证**：current gate、TypeScript strict、Vite、Rust test/fmt/clippy、包体验证、文档链接和 `git diff --check`。
7. **真实桌面回归**：Mini、Workbench、Settings、Wizard、托盘、窗口找回、主题、贴边、DPI；平台环境不足则不得判定删除安全。
8. **回退**：保留单独提交；失败时仅回退该候选，不撤销其他用户修改。

## v1.0.7 建议

- 本版不设“删除文件数量”目标。
- 优先消除伪当前合同和错误入口，再做前端一个边界、Rust 一个边界的渐进治理。
- 版本化脚本、历史文档和 Spike 先建立 lifecycle 索引，不在同一版本中大规模迁移。
- 任何体积优化都必须由启动、内存或维护数据触发，而不是由文件年龄触发。
