### 范围变化判断

- v1.0.7 已不再只是“纯工程可信版本”候选；项目所有者明确加入加班、工时和月度总结方向。
- 不建议把全部观察自动纳入同一版本。先在 `/idea` 中比较“维护可信主线”和“产品增强主线”的依赖、风险和交付组合。
- 加班与月度总结不得在没有日期归属、费率、历史重算和实际/计划工时定义时直接进入 PRD。
- 置顶、调整今天和 Workbench/Mini 重叠可在 `/idea` 中作为高确定性行为候选优先收敛。

### V107-P0-002 当前 CI 聚合门禁

- 来源：V107-REV-002
- 目标：CI 必须执行当前版本聚合，而不是永久锁在旧版本脚本。
- 候选方案：新增无版本名 `verify_windows_current.ps1` 作为 CI 稳定入口，由其声明当前 release contract；版本化脚本继续保留历史复验。
- 通过标准：CI 同时运行 TS strict、Vite、完整 cargo test/fmt/clippy、架构行为测试、文档检查和当前版本定向合同。
- 失败保护：入口声明版本与 package/Cargo/Tauri 不一致时立即非零退出。

### V107-P0-003 配置 v8 唯一合同

- 来源：V107-REV-003
- 目标：Rust、TypeScript、JSON Schema、默认值和迁移测试对同一配置结构达成一致。
- 必须覆盖：`theme_mode`、`mini_edge_auto_hide`、`mini_edge_dock`、`paid_rest`、`unpaid_rest`、`calendar_dataset_version=cn-2025-2026-v1`。
- 通过标准：任何一层字段、枚举、版本或默认值漂移时测试失败；旧 v6 合同若保留，必须明确标记 historical，不得继续名为当前合同。

## P1：推荐进入 v1.0.7

### V107-P1-001 应用版本单一事实源

- 来源：V107-REV-008
- 用户价值：关于页和更新检查永远显示正在运行的真实版本。
- 影响范围：React、Tauri app metadata、打包验证、更新测试。
- 风险：浏览器原型没有 Tauri metadata，需要显式预览 fallback。
- 测试缺口：当前门禁未比较 App 可见版本和包版本。

### V107-P1-002 桌面窗口错误语义

- 来源：V107-REV-004
- 用户价值：窗口打不开或隐藏失败时能得到反馈，不会把当前窗口意外切换为另一个 query。
- 影响范围：`App.tsx`、`WindowFrame.tsx`、`windowService.ts`、日志、组合行为测试。
- 前置测试：browser preview fallback、desktop invoke failed、hide failed、窗口找回。

### V107-P1-003 渐进式前端职责提取

- 来源：V107-REV-005、V107-REV-006
- 推荐边界：从 `App.tsx` 提取 Workbench/Settings/Wizard 页面所有权；从 `model.ts` 提取日历加载与 cache hook。
- 限制：不引入新全局状态库；不改变 IPC、配置或收入公式。
- 回退：每个边界独立提交，保留原导出 API。

### V107-P1-004 渐进式 Rust 窗口职责提取

- 来源：V107-REV-005
- 推荐边界：先提取 WindowSpec/错误映射，再选择 tray 或 Mini edge 之一；不在同一版本同时拆完。
- 限制：command 只做参数与服务桥接；不改变窗口尺寸、位置、托盘和隐藏语义。
- 回退：原命令名与 Tauri 注册不变。

### V107-P1-005 验收证据耐久合同

- 来源：V107-REV-007
- 推荐：仓库内保存脱敏 manifest、候选哈希、环境、步骤和结论；原始截图/日志放稳定外部存储并记录不可变索引。
- 禁止：把包含用户名、绝对路径、工资或完整日志的原始证据直接提交。

### V107-P1-006 Windows 支持矩阵

- 来源：V107-REV-011
- 最小范围：Windows 10 单显示器核心路径；Windows 11 双显示器窗口找回与贴边。
- 环境不足：标记待人工补证，不得写为通过。

- V107-P0-001 至 V107-P0-003。

- 不做架构拆分。

### 推荐方案
