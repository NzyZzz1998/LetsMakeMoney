# LetsMakeMoney v2 架构与安全债务交接
## 交接原则

v1.0.8 以稳定收官为目标，不对 `App.tsx`、`model.ts` 或 Rust `lib.rs` 做整体重写。本清单记录下一主版本的证据入口与前置门禁，不代表 v2 已排期或已实现。

| 债务 | 当前事实 | 风险 | v2 前置测试 | 停止条件 |
| --- | --- | --- | --- | --- |
| `App.tsx` 页面编排 | 多窗口页面、设置和弹窗集中 | 修改局部 UI 时扩大回归面 | 四窗口路由、关闭、草稿、主题组合测试 | 拆分不能保持行为等价即撤回 |
| `model.ts` Dashboard 生命周期 | 权威同步、本地 tick、日历缓存和浏览器 fallback 集中 | 时间与窗口生命周期认知成本高 | 睡眠恢复、跨夜、时区、隐藏恢复、fallback 边界 | 新模型没有单一权威来源则停止 |
| Rust `lib.rs` 窗口编排 | 托盘、窗口事务、贴边、置顶与 WebView 生命周期集中 | 原生修复回归范围大 | 托盘、找回、贴边、DPI、失败补偿 characterization tests | 真实 GUI 回归成本超过收益则不拆 |
| 多窗口状态所有权 | 各 WebView 保留局部状态并读取权威 Rust | 存在重复同步和瞬时收敛成本 | 请求频率、配置事件、隐藏/恢复测量 | 无可量化收益不引入共享 store |
| TimeService | 已有前端时间抽象，Rust/前端边界仍分散 | 时区与 wall-clock 变化可能漂移 | 睡眠、手动改时、时区、DST fixture | 无跨平台需求时不扩大抽象 |
| CalendarProvider | 当前仅中国大陆离线合同 | 扩展国家会污染现有日历语义 | provider schema、来源、许可、回滚 | 没有明确地区需求不实施 |
| 配置迁移 | config v8 与 overtime v2 分别迁移 | 多文件事务和降级工具复杂 | 幂等迁移、备份、旧版导出、崩溃恢复 | 不能证明旧数据安全则停止发布 |
| CSP | 正式配置仍为 `null`，隔离候选曾破坏 Mini bootstrap | WebView 安全加固未完成 | 全部窗口、IPC、资源、更新、fallback 和打包验证 | 任一主链路失败即撤销候选 |

## 明确不在 v1.0.8 实施

- 新全局状态库或跨 WebView 快照广播；
- App/model/lib 整体拆分；
- 在线日历、账号、云同步、安装器或自动更新；
- CSP 直接启用；
- 宠物或 PetManager 回归主线。
