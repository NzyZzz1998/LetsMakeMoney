## 4. FR-017 业务规则追踪

| 规则 | 数据合同 | 自动测试 | 原型/GUI 验收 |
| --- | --- | --- | --- |
| 计划班次动态上限 | `min(下班至下一真实上班间隔, 1440分钟)` | 跨周末、节假日、手动调整、大小周 | 显示边界来源、下一工作开始和动态上限 |
| 自然周末手动设工作日 | `origin=manual_weekend_work`，默认 `min(480, maximum_minutes)` | 同一事务创建日期覆盖与加班记录 | 同一弹窗编辑，应用后同时出现工作日与加班标记 |
| 官方调休工作日 | 不自动创建加班 | 官方调休日负向 fixture | 界面不出现联动默认值 |
| 普通休息日独立录入 | `origin=independent`，上限 1440 分钟，无默认 | 0、边界、24h、超限 | 加班弹窗为空，用户主动输入 |
| 恢复自动/休息状态 | 对 `linked_override_date` 关联记录询问保留或删除 | 保留、删除、取消、失败回滚 | 弹窗明确显示选择；不得静默删除 |
| 历史 v1 记录 | 迁移后 `origin=independent`、`boundary_snapshot=null`，不裁剪 | 超过新上限的历史记录保持原值 | 查看不报错；修改时才按新规则校验 |
| 费率与跨夜 | 保留分钟精度、1.0×费率快照、`owner_date` | 工资变化不追溯、跨夜归属 | 月度总结只显示加班时长，不显示加班收入 |
| 原子事务 | journal + 临时文件 + fsync + 原子替换 + 恢复 | 每个事务阶段故障注入 | 失败保留输入和旧数据，允许重试 |

## 6. 原型追踪

- 交付：`doc/prototypes/v1.0/index.html`、`app.js`、`styles.css`、`README.md`。
- 必测场景：计划班次动态上限、自然周末联动、普通休息日独立录入、关联记录恢复自动、保存失败回滚。
- 必测主题与缩放：浅色、深色；100%、125%、150% 模拟。真实 Windows DPI 留到实现后验收。
- 浏览器模拟不证明 Rust 原子文件事务、系统 Logo 缓存、真实窗口边界或正式候选身份。
- 2026-08-04 定向结果：27/27 通过；控制台错误 0、页面异常 0；动态 15 小时上限、超限拒绝、1.25 小时保存、周末默认 8 小时联动、原子失败保留输入、关联删除和休息日 24 小时独立录入均已覆盖。
- 浅色/深色 × 100%/125%/150% 浏览器模拟无水平溢出；该结论不得替代真实 Windows DPI 验收。

## 7. 开发承接门禁

只有以下条件同时成立，才可生成 `dev_plan_v1.0.F.md` 与 `progress_v1.0.F.md`：

1. 项目所有者确认 `prd.md` 与本矩阵。
2. 原型完成动态上限、周末联动、关联删除和失败回滚验证。
3. 当前 dirty 候选逐项决定纳入、重做或舍弃，并重新锁定干净 HEAD。
4. FR-017 schema v2、原子事务和迁移 fixture 可由开发直接实现，不存在未决产品语义。
5. 冷启动、CSP、Windows 10 与多显示器的停止边界不被扩大。
