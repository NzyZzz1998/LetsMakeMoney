## 1. 执行基线

本阶段只实施已确认的 v1.0.F PRD，不重新定义产品需求。开发事实由 PRD、追踪矩阵、本计划和 progress 共同约束。当前 dirty 工作区包含品牌与视觉候选，必须逐文件判定“纳入、重做、舍弃或转交”，不得覆盖用户已有变更。

实施原则：

1. 一个模块一批修改，先补行为测试，再改变行为。
2. 用户数据安全、加班历史兼容和候选身份优先于视觉完成度。
3. 条件 Spike 必须以继续、停止或回退结论收口。
4. v1.0.7 已发布行为必须通过回归门禁保护。
5. 不提交、不推送、不打 tag、不创建 Release，直至项目所有者明确授权发布收口。
