## 收官候选的冻结顺序

1. 确认公开数字版本和“收官”定义。
2. 对当前 dirty diff 逐文件分为进入、舍弃、仅审查证据三类。
3. 将最终 Logo 源、生成器和产物合同纳入版本门禁。
4. 先在开发候选完成真实 GUI 与 DPI 复验。
5. 提交后从干净源重建，不继承 dirty 候选哈希。
6. 复跑 current gate、包验证、更新检查和 GitHub 回下载验证。

## 不应被重开的已稳定口径

- 月薪、日薪、时薪、秒级收益和分币尾差。
- 单休、双休、大小周、官方/估算日历和日期调整事务。
- 跨夜 owner date、休息阶段和加班费率快照。
- config v8、迁移、原子保存和失败保护。
- 原生托盘继续使用系统样式。

## 结论

v1.0.F 的合理定位是**品牌、视觉、发布身份和少量陈旧合同的最终收敛**，而不是再次扩展业务能力。当前候选可以成为输入，但必须经过范围冻结、干净构建和真实桌面复验后才能转化为发布对象。
