# LetsMakeMoney v1.0.F 瘦身与归档候选

> 本文件只列候选、依赖和删除门禁。本轮未删除、移动、归档或还原任何文件，也未清理当前用户修改。

## 总体判断

- Git 仓库没有需要立刻大清洗的异常体积；主要占用来自被忽略的本机编译缓存。
- v1.0.F 收官前可以清理本机派生目录和未采用的 Logo 探索中间产物，但必须与产品代码提交分开。
- 历史 release、许可、配置迁移、v0.9 回退、Figma 和 Spike 不能仅凭“旧”直接删除。

## 可直接清理的本机派生对象

以下对象不受 Git 跟踪，能够由依赖安装、构建或验收重新生成。清理前必须确认没有正在运行的构建、候选 EXE 或需要保留的原始验收证据。

| 对象 | 本轮测得体积 | 用途 | 清理条件 |
| --- | ---: | --- | --- |
| `apps/windows-v1/src-tauri/target/` | 约 7,622MB | Rust/Tauri 编译缓存 | 无构建进程；后续允许重新编译 |
| `.artifacts/` | 约 183MB | 本地候选与构建产物 | 已核对无唯一验收原件或正式附件 |
| `apps/windows-v1/node_modules/` | 约 108MB | npm 依赖 | lockfile 存在且可重新安装 |
| `.tmp_acceptance/` | 约 10MB | 本地验收临时证据 | 耐久摘要已落仓库，原始证据另有归档或允许丢弃 |
| `apps/windows-v1/dist/` | 约 2MB | 前端构建结果 | 不被运行中的候选引用 |

这些是本机磁盘治理，不应形成“源码瘦身了 7.9GB”的错误发布宣传。

## 最终选择后可收敛的品牌探索

当前 `doc/prototypes/v1.0/` 有 20 个未跟踪 Logo 探索文件，合计约 9.0MB。项目所有者已选择 L2“燕麦石墨”。

### 必须保留

- 最终 L2 设计源与颜色/尺寸合同。
- `apps/windows-v1/brand/app-icon-l2.svg`。
- 确定性图标生成脚本。
- 应用使用的 ICO/PNG 与哈希证据。
- 一份记录候选、选择理由和最终决定的轻量说明。

### 可在确认后移出当前交付面

- 未采用的大尺寸材质探索 PNG。
- 重复的浏览器预览截图。
- 只用于中间比较、没有独立决策价值的候选 HTML。
- 已被后续轮次完整替代的预览版本。

### 删除/归档门禁

1. 最终 L2 在 16/24/32/48/64/256 像素及 ICO 多尺寸下通过人工审阅。
2. 任务栏、托盘、窗口标题、资源管理器和 About 使用一致资产。
3. 生成器在干净环境可重复产生相同哈希。
4. 原型或正式文档不存在对待移除文件的链接。
5. 删除动作与产品代码提交分离，可单独回退。

## 本轮禁止的清理方式

- 不用 `.gitignore` 掩盖已经跟踪的事实文件。
- 不把正式 Release 附件与本地 candidate 混在一起删。
- 不删除当前 dirty 工作区中用户尚未确认的实现。
- 不因文件名带 `spike`、`prototype`、`old` 或版本号就认定无用。
- 不在品牌/视觉功能提交中顺带做大规模目录移动。

## 推荐执行顺序

1. 完成 v1.0.F `/idea`，确认最终版本身份和候选范围。
2. 冻结 L2 品牌资产，建立唯一生成与哈希合同。
3. 将未采用 Logo 探索分为“保留决策证据”和“可移除中间产物”。
4. 独立清理可重建的本机构建缓存。
5. v1.0.F 发布后，再为 v2 建立 App/model/lib 治理计划。

## 结论

当前最有价值的“瘦身”不是删除历史，而是把**正式发布、开发候选、设计探索、耐久证据和可重建缓存**分层。仓库级删除应晚于 v1.0.F 范围冻结；本机缓存可在确认无活动任务后单独清理。
