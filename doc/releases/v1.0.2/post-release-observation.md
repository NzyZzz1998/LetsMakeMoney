## 确认缺陷

### V102-BUG-001 启动时短暂误报无法计算

- 证据状态：已确认。
- 严重度：Major。
- 表现：有效配置启动后，界面先显示“暂时无法计算”，随后自动恢复正常收入结果。
- 日志：首次 `earnings.authoritative_sync.requested reason=startup` 后出现 `calculation_unavailable`，后续同步成功。
- 用户影响：会让用户误以为配置损坏或收入计算失败。
- 分流：v1.0.2 必修。
- 当前状态：已修复并通过新解压候选 GUI、日志和真实错误保护复验。

## 候选而非缺陷

- 多个可见窗口各自执行 30 秒权威同步，可能产生重复日志和计算；当前没有造成结果错误，需要共享状态技术评估。
- 调休工作日详情仍显示“自动判断：工作日”，可考虑更明确的“调休工作日”文案。
- 跨夜班次详情标题仍写“今天的收入进度”，日期行已正确显示归属日；属于文案候选。
- 今日安排时间轴、迷你视图拖拽横线与尺寸、日历图标、阶段化倒计时文案，以及“今天”和选中日期的视觉区分需要下一轮统一优化。

上述候选不进入本次最小修复。

## v1.0.2 定向复验结论

- 有效配置启动时不再显示假失败。
- 瞬时 `calculation_unavailable` 只触发有限重试，日志记录 `retry_scheduled` 后成功完成。
- 受控真实配置错误进入配置恢复路径，没有无限重试或伪装成功。
- 日历、日期调整、跨夜班次、秒级收益和更新检查没有回归。
- 以原“启动热修”范围判断时无阻塞；该结论保留为历史定向证据。
- 通知区真实鼠标左键继续保留为人工补证。

2026-07-27，项目所有者将 v1.0.2 调整为正式优化版本。启动修复证据继续有效，但不再代表整个 v1.0.2 可发布。正式版本需从 `/idea` 重新完成范围、PRD、开发和最终验收。
