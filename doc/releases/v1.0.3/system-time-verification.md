# v1.0.3 系统时间与稳定性验收

## 适用对象

本清单只接受锁定 SHA256 后、从全新目录解压运行的 v1.0.3 最终候选。开发服务器、旧解压目录、Debug 进程和身份变化后的旧证据均不能替代最终候选。

验收前记录并在结束后恢复：

- Windows 当前日期、时间、时区和自动设置开关；
- `%APPDATA%\io.letsmakemoney.windows` 下的配置与日志；
- 运行中 LetsMakeMoney 进程；
- 候选 Zip、EXE、WebView2Loader 和年度日历数据 SHA256。

## 睡眠与恢复

### 工作阶段跨过休息边界

1. 使用受控配置令当前时间处于工作阶段且距离休息边界较短。
2. 记录迷你视图、今日详情、金额、阶段、owner date 和日志。
3. 让 Windows 真实进入睡眠并跨过休息开始时间。
4. 恢复后记录首次可见画面和收敛耗时。
5. 要求 5 秒内显示休息阶段，金额停止增长，边界倒计时正确，日志出现恢复检测和一次权威同步。

### 休息阶段跨过恢复工作边界

重复上述步骤，但从休息阶段睡眠并跨过恢复工作时间。恢复后 5 秒内应进入工作阶段，秒级收益继续增长。

## 系统时间跳变

分别执行：

1. 时间向前调整，跨过休息或下班边界；
2. 恢复原时间；
3. 时间向后调整，回到较早业务阶段；
4. 恢复原时间。

每次操作都核对阶段、金额、owner date、今日安排、日历和日志。允许本地画面短暂保持，但 5 秒内必须由权威结果收敛。不得出现金额负增长、重复 timer 或配置损坏。

## 时区变化

1. 记录当前时区 ID 与 UTC offset。
2. 切换到一个 offset 不同的真实 Windows 时区。
3. 重新聚焦或恢复应用，核对阶段、owner date、金额和日历。
4. 恢复原时区，再次核对。

日志必须出现 `schedule.timezone_changed`，且每次变化只触发一次恢复同步。未执行真实 Windows 时区切换时只能写“待人工补证”，不得写通过。

## 两小时稳定运行

使用 `scripts\collect_v103_stability.ps1` 对最终候选进程连续采样至少 120 分钟：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts\collect_v103_stability.ps1 `
  -ProcessId <PID> `
  -DurationMinutes 120 `
  -EvidenceDirectory <证据目录>
```

门禁：

- 进程全程存活，无崩溃或不可恢复空白窗口；
- timer 未重复注册；
- 30 秒权威同步请求总数不超过 245 次；
- `debug.log` 增长不超过 2 MiB；
- CPU、工作集、私有内存、句柄和线程趋势被完整记录；
- 不将短时采样描述成两小时稳定性证据；
- 稳定性过程中若候选身份变化，证据作废并重跑。

CPU 或内存存在明显单向增长时应进入缺陷分析；单凭短时峰值不得宣称内存泄漏或性能通过。
