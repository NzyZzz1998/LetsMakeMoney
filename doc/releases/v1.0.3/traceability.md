# LetsMakeMoney Windows v1.0.3 需求追踪矩阵

## 1. 追踪规则

- 上游需求以 `V103-IDEA-xxx` 为唯一 Idea 来源。
- 正式开发与验收入口为 `FR-001` 至 `FR-008`。
- `V103-IDEA-003` 已完成性能技术 Spike，仅作为 `FR-005` 和 `FR-007` 的证据，不重复进入开发任务。
- `V103-IDEA-004` 只承接隐藏窗口生命周期暂停与恢复；共享 React store、跨 WebView 快照广播和单一永久同步所有者不在本版范围。
- `V103-IDEA-009` 不独立实施，只允许与本轮需求直接相关的局部拆分。
- PRD、实现、测试和验收状态不得通过本矩阵互相推断；每个阶段仍需保留独立真实证据。

## 7. 数据状态追踪

| 覆盖状态 | 可计算 | 可查看日历 | 可新增日期调整 | 用户标签 | 允许来源 |
| --- | --- | --- | --- | --- | --- |
| `official` | 是 | 是 | 是 | 官方日历 | 已验证年度数据 |
| `estimated` | 是 | 是 | 是 | 估算日历 | 单休、双休或大小周配置 |
| `stale` | 是，限同范围最后可信结果 | 是 | 否 | 数据过期 | 同目标月份最后成功结果 |
| `integrity_error` | 否，除非保留同范围 stale | 无可信结果时否 | 否 | 加载失败 | 不得自动转估算 |
| `loading` | 保留当前可信展示 | 保持布局稳定 | 否 | 正在加载 | 正在读取/校验 |

日期判定优先级固定为：

```text
手动日期调整 > 已验证官方年度数据 > 休息模式估算
```

`stale` 是展示保护状态，不是新的业务来源；完整性错误也不是 unsupported。

## 9. 范围保护

| 项目 | 本版结论 | 重新进入条件 |
| --- | --- | --- |
| 共享 React Dashboard store | 不做 | 新测量证明用户可见收益且通过独立技术 Spike |
| 跨 WebView 快照广播 | 不做 | 共享所有权方案获单独批准 |
| 单一永久同步所有者 | 不做 | CPU、请求与原型门槛均满足 |
| 在线日历服务、应用内下载或用户导入 | 不做 | 后续版本重新进入 Idea/PRD |
| 虚假或推测的 2027 官方数据 | 禁止 | gov.cn 正式公告发布并通过年度更新合同 |
| 宠物、账号、云同步、安装器、多平台 | 不做 | 后续独立版本决策 |
| 全局状态或技术栈重写 | 不做 | 后续独立技术选型 |

## 10. 开发承接门禁

进入 `dev_plan_v1.0.3.md` 前必须满足：

1. 项目所有者确认 [完整 PRD](prd.md)。
2. FR-001 至 FR-008 与本矩阵无范围冲突。
3. 原型中的官方、估算、stale、加载失败状态通过人工检查。
4. 仍未确认的系统证据保留为开发后发布阻塞门禁，不提前写为通过。
5. 不生成虚假年度数据，不将性能 Spike 结论夸大为内存泄漏或 CPU 修复。

以上门禁已于 2026-07-30 满足，开发计划与进度清单已经生成。该状态只代表开发承接完成，不代表业务实现开始或通过。
