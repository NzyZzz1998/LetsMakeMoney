# LetsMakeMoney Windows v1.0.5 高保真交互原型
打开 [index.html](index.html) 可评审 v1.0.5 推荐方案中的 Mini 隐私状态机、日历导航层级与限定窗口单表面 Spike。**本轮不以低保真线框替代**；该文件与 PRD、追踪矩阵共同构成开发前 UI/交互事实源。

## 1. 原型定位

- 延续 v1.0 的产品结构，不代表业务代码已经实现 v1.0.5。
- 顶部评审控制条不属于正式产品，仅用于切换窗口、状态、主题、DPI 和候选方案。
- 所有产品窗口均由可编辑 HTML/CSS 组成，不嵌入运行截图。
- 当前公开基线仍是 v1.0.4 Stable；原型中的 v1.0.5 表示待确认需求版本。
- 不恢复宠物，不重写设计系统，不改变收入、日历数据源或配置事务口径。

## 2. 评审控制条

| 控件 | 用途 | 需要回答的问题 |
| --- | --- | --- |
| 窗口 | 切换 Mini、今日工作台、Wizard、Settings | 四个入口是否保持既有信息架构 |
| Mini 隐私停靠 | 模拟悬浮、左侧收起、右侧收起 | 首次贴边、展开和再次收起是否可理解 |
| 今天 A / B | 比较角标与底部短标签 | 哪种表达在复合业务状态上更清楚 |
| 单一表面 / 旧边界 | 比较限定窗口边界 | 是否能消除“框中框”且不损失 Windows 窗口感 |
| 业务状态 | 切换阶段、休息日与跨夜 | 隐私竖条和详情文案是否来自真实阶段 |
| 日历状态 | 切换官方、估算、加载、过期、失败 | 正常态是否安静、风险态是否仍足够明显 |
| 主题 / DPI / 长内容 | 评审浅深主题与三档 DPI | 是否存在裁切、对比度或长文案退化 |
| 模拟写入失败 | 检查保存与日期调整失败 | 草稿、旧配置与错误反馈是否被保护 |

## 3. Mini 隐私状态机

### 状态

1. `floating_expanded`：完整 Mini，未贴边。
2. `docked_expanded`：完整 Mini 已停靠左侧或右侧。
3. `retract_pending`：释放拖拽后等待 600ms，允许用户继续操作。
4. `retracted_tab`：只保留 28px 隐私竖条。
5. `revealing`：悬停、聚焦或点击后约 180ms 展开。
6. `fallback_expanded`：几何、DPI 或工作区异常时保持完整可见。

### 隐私竖条文案

竖条只显示非收入状态，不显示月薪、今日已赚、日薪、时薪、百分比或带薪/不带薪差异：

| 业务状态 | 竖条文案 |
| --- | --- |
| 加载中 | 正在同步 |
| 失败 | 点击查看 |
| 上班前 | 距离上班 38分 |
| 工作且休息前 | 距离休息 38分 |
| 休息中 | 距离复工 38分 |
| 工作且休息后 / 跨夜 | 距离下班 4时38分 |
| 工作结束 | 今日工作结束 |
| 普通、带薪或不带薪休息 | 今日休息 |

原型数字为固定模拟数据，只验证文案、布局和可找回性；正式实现必须消费权威 Dashboard 边界，不得另建倒计时算法。

### 关键交互

- 左右停靠使用相同状态机，文本方向不镜像。
- 竖条悬停、键盘焦点或点击均可展开。
- 指针离开且没有焦点、菜单、对话框或拖动锁时再次收起。
- 首次拖到边缘后不依赖额外点击或 `pointerleave` 才能收起。
- 托盘隐藏不是贴边收起；托盘隐藏仍使用原生窗口生命周期。
- 关闭今日工作台只回到 Mini，不等于显式找回；若真实事件链无法复现异常，不改写 focus/shown 语义。

## 4. 日历状态与“今天”候选

### 正常与风险状态

- 官方数据正常：不显示常驻绿色来源块，也不在 Mini/详情首屏重复显示“官方”。
- 估算、加载、过期和失败：继续显示明确来源、影响与重试入口。
- 风险提示不得覆盖日期网格，也不得把估算写成官方数据。

### 复合状态

日期单元格同时保留：

- 业务层：工作日、休息日、调休、手动工作日、带薪休息、不带薪休息；
- 导航层：今天、当前选中日期；
- 交互层：hover、键盘焦点、disabled、stale。

业务底色优先保留；选中日期使用单元格边框；手动/调休使用来源角标；“今天”不得用第二个同尺寸圆环与选中边框竞争。

### 两套候选

- **A（推荐待确认）**：左上角 16px 中性“今”角标，右上角保留“手 / 调”来源角标。
- **B（备选）**：日期底部短标签“今天”，在极窄单元格中需要额外关注空间占用。

项目所有者选择 A 或 B 后，结论回写到 `doc/releases/v1.0.5/prd.md` 的 FR-007 和验收矩阵；若暂不选择，FR-007 不阻塞其他需求进入开发。

## 5. 限定窗口单表面 Spike

覆盖 Workbench、Settings、Wizard；Mini 只做隐私和回归，不参与整体重绘。

- **单一表面**：一个圆角裁切所有权、一个边界、一个窗口阴影，标题栏仅作为内部区域。
- **旧边界**：用附加外层环模拟 v1.0.4 的“框中框”对照。
- 同时检查浅色、深色、100%/125%/150% DPI、四角裁切、标题栏拖动、关闭按钮和内部滚动。
- 原型只能验证结构与视觉方向；是否采用必须由真实 Tauri 壳截图和透明 WebView 四角证据决定。
- Spike 失败时保留 v1.0.4 窗口边界，不阻塞 FR-001 至 FR-007、FR-009 和 FR-010。

## 6. 继承回归范围

- Mini 长金额、加载、错误、上班前、工作、休息、下班后、休息日和跨夜状态；
- Today 与 Calendar 的来源一致性；
- 日历日期调整的应用、取消、失败和旧数据保护；
- Wizard 三步、大小周用户选择、休息时长和事务保存；
- Settings 的主题预览、保存、无变化、失败、取消和关闭；
- 托盘隐藏、找回及窗口位置持久化；
- 浅色与深色主题；
- 100%、125%、150% DPI 与长内容。

## 7. 验证方式

### 浏览器原型

1. 使用控制条逐一切换四个窗口。
2. 左右停靠 Mini，检查 28px 竖条、不同业务文案、展开和收起。
3. 切换今天 A/B，检查今天 + 选中 + 手动/调休叠加。
4. 切换官方、估算、加载、过期和失败，确认只有风险态占提示位。
5. 切换单一表面/旧边界，检查三个限定窗口。
6. 在浅色/深色、100%/125%/150% 和长内容下复查。
7. 检查浏览器控制台与页面错误。

### 2026-07-31 实际浏览器验证

使用本机 bundled Chromium 对 `index.html` 执行了无头浏览器交互验证，结果如下：

- JavaScript 语法检查通过，浏览器控制台错误 `0`，页面异常 `0`；
- 1600×1000 桌面视口无页面级水平溢出；
- 900×900 窄视口无页面级水平溢出，Wizard 实测内容框为 760×560，内部无水平滚动；
- Settings 实测内容框为 720×540，浅色/深色均可切换并在过渡结束后完整可见；
- 左右隐私竖条实测可见宽度为 28px；工作中显示对应阶段倒计时，普通/带薪/不带薪休息统一显示“今日休息”；
- normal official 状态的首屏来源块隐藏；error 状态提示与“重试”入口可见；
- “今天 A / 今天 B”与“单一表面 / 旧边界”可交互切换，DOM 状态与画面同步；
- 本轮截图仅用于临时视觉校准，未写入仓库或原型资源。

该结果只证明浏览器高保真原型的交互和布局合同成立，不替代真实 Tauri 壳、Windows DPI、透明四角、原生停靠与窗口事件验收。

### 真实 Windows 门禁

浏览器缩放不等于 Windows DPI。开发后仍必须在真实 Tauri 壳中验证：

- 工作区几何与首次拖放事件时序；
- 左右边缘、任务栏边缘和窗口找回；
- 真实 100%/125%/150% DPI 四角与命中区；
- 关闭 Workbench 时的窗口标签、focus、shown 和 reveal 日志；
- Mini 隐私信息在截图、任务栏缩略图和托盘流程中的边界。
